# The C runtime: what mirrors the evaluator

The runtime under this directory is the C11 half of CPL's one native core
(`spec/cabi.md` Section 2). Where it computes what the reference evaluator
computes, it transcribes the evaluator's function rather than
reinventing it: the builtins (Section 2.7), the bigint, UTF-8, value text,
`quote_text`, the JSON reader and writer, and the text kernels (Section
2.9), and the parts of evaluation the emitted code calls into (Section 3).
Each such C function carries a `/* mirrors cpl_eval::<path> */` comment
directly above its definition, naming the Rust function it follows; a
comment may add what differs in form (an explicit work stack where the Rust
recursion is bounded by the host stack, an out-parameter where Rust returns
a value), never a difference in result.

When the evaluator changes, this index is the list of C functions to
revisit. The differential suites hold the two to each other (`spec/toolchain.md`
12.6: D1 to D8, the runtime fuzzing of D7 in particular), and
`crates/cpl-rt/tests/mirrors.rs` holds this file to the comments: every
named path is a function of `crates/cpl-eval/src`, every callable builtin
has its comment, and the table below lists exactly the comments, in file
and line order (`UPDATE_MIRRORS=1 cargo test -p cpl-rt --test mirrors`
rewrites it).

This file is not a runtime file: the build embeds only the `*.c` and `*.h`
files of this directory (`spec/toolchain.md` 1.12).
